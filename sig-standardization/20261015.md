### Formal appeals process for suspected false positives

sponsor: @mbuechse / @janiskemper

- sometimes a test fails in a formal sense, but
  - either (a) test specification defect: we should be inclined to treat the result as acceptable,
  - or (b) test implementation defect: we realize we are not confident that the result is correct, calling for further research
- case in point
  - as for (a): see issue [standards#982](https://github.com/SovereignCloudStack/standards/issues/982)
    - some networking testcases fail
    - it turns out some of them test implementation details, and some are too strict (even in upstream's opinion)
    - so this would be in instance of case (a): the tests fail correctly, but the tests are not relevant, so we should count the result as acceptable
  - as for (b): see PR [standards#1292](https://github.com/SovereignCloudStack/standards/pull/1292)
    - an e2e testcase fails
    - the root cause is that Sonobuoy uses a service account that doesn't have full permissions
    - the e2e guidelines don't specify that permission should or shouldn't be restricted in this way!
    - Sonobuoy can be instrumented in a way that full permissions are given, and then the test is indeed passed
    - bottom line: the FAIL was a false positive (this is an instance of case (b): we cannot be confident that the result is adequate)
- in such instances, the test subject in question will appear red (FAIL) until the root causes are found and the problems sorted out
- Q: do we want to grant our partners a grace period (say, 2 weeks) for investigating issues of this kind, where the testcase result will be converted into DNF (did not finish), so they don't endanger the overall compliance?
- if yes: we need to specify a formal appeals process; the partner would have to send a formal request for appeal to the certification assessment body, laying out reasonable suspicion that the FAIL result in question is indeed of this kind; the latter body would have to respond in time and either grant or deny the request for appeal; then some instrument would have to be put in motion that, within the grace period, automatically converts the result to DNF
- said instrument needs to be implemented
- no objections in general
- _AI @mbuechse: write issue(s), PR(s) accordingly_
