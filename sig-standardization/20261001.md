### SCS-compatible IaaS v6

sponsor: @mbuechse

- amend scs-0128 to specify how much Tempest may be amputated via toggles (could go into Supplement)
  - e.g., one can toggle "IPv4 not present", and then related tests will be skipped even if part of the list
  - viewpoint 1: exceptions need to be explicitly warranted (for instance, if a certain section of test cases does not apply to a special case such as a private cloud or air-gapped environment)
    - make this transparent (add a remark to certification status page and certification application form)
    - amend standard to this effect
    - how would the Forum govern what exceptions are acceptable?
      - the Forum should be consulted in those cases where no exceptions are mentioned in the standards
  - viewpoint 2: this standard is about correctness (as opposed to completeness) -- to verify that features work IF and WHEN they are available
    - reply: scs-0128 is a successor to OpenStack-powered Compute, and we want to keep the same baseline (supposedly not just correctness, but also completeness)
  - and be more explicit about requirements (as opposed to 'black box' catch-all scs-0128)
    - --> work towards superseding scs-0128 with our more native standards
- discussion regarding ipv4/ipv6
  - at present, ipv4 is required (according to scs-0128)
  - scs-0126 is not yet in effect; it would require v6 and (redundantly) recommend v4
  - standardizing some desireable state that's not yet de-facto industry standard could be problematic
  - reference implementations should precede standard
- FYI: stabilization imminent

### Recap SCS Hackathon #7

sponsor: @depressiveRobot

(not discussed; for the record)

- Results & minutes: https://input.scs.community/s/9lLDE1dcZF
- short summary
  - Group I: CRUD API for KaaS Clusters
    - full-fledged API vs. template based API
    - discovery / self-description endpoint
    - outcomes
      - keep complexity low on client/customer side -> rules out template based API
      - however, CSPs don’t want to offer yet another API to provision clusters -> rules out full-fledged API
      - self-description needed in both cases
    - action item: draft standard for discovery / self-description
  - Group II: Testing services for SCS PaaS
    - test installations of different kinds of application
    - outcomes
      - tutorial on how to create a Syself KaaS cluster with GPU for AI workloads
      - every tested application needs a load balancer
      - everyone needs storage, so it need to be offered
    - action items
      - draft standard for load balancer
      - draft standard for storage (classes)
  - Group III: KaaS Security
    - research on NIST and other upstream projects regarding k8s security
    - outcomes
      - fulfill all technical NIST standards
      - start working on SCS-open
    - action item: go through NIST list and decide if it should be incorporated into a standard
  - discussion about scs-0210-v2 and offering of last three minor versions
    - action item: continue discussion in SIG Std/Cert
