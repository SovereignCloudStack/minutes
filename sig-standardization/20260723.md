### Adding SCS-0128 to compliance checks

sponsor: @toothstone

I've assembled a [minimal Tempest config](https://pads.alasca.cloud/scs-0128-minimal-tempest-config?view) to run most of the ~260 SCS-0128 Tempest tests.

Most settings are static, many of the cloud-dependent ones can be fetched/set up via the OpenStack API.

Major hurdles that remain:
- 2 static user accounts (with passwords) in two separate, empty projects are required
  - are CSPs willing to provide those
  - how are these credentials added to the compliance workflow
- fixed network required, external network needs to be discovered
- image format enforcement must be disabled to run ~10 tests, but that is incompatible with at least my cloud (415 media type unsupported: octet/stream) (setUpClass tempest.api.image.v2.test_images.ListUserImagesTest)

Is this something we want to pursue? Automating & integrating the SCS-0128 test could be a great help to both CSPs and the certification body by reducing complexity and ambiguity.

Discussion (lean SCS operator coffee):

- do not use Tempest in test suite
  - requires all kinds of preconditions (see above)
  - leaks resources that cannot always be removed by user
  - also, Tempest seems a little messy
- add scenarios via OpenTofu
  - competition for best scenarios
