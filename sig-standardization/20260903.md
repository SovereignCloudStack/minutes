### Harmonizing SCS-compatible IaaS environments / SCS core?

sponsor: @mbuechse

- Can we make it more explicit what is available on each and every SCS environment?
- Case in point: flavors (yet again)
  - right now, many CSPs offer SCS- flavors that are neither mandatory nor recommended (because they want to offer more CPUs, more disk space, or GPUs)
  - the SCS naming convention can help users feel at home, provided that they 'speak it' (which is quite a learning curve)
  - however, users don't readily see whether they are using a standard flavor, one that is available on every SCS-compatible IaaS environment
- proposal by @garloff: PR [standards#1266](https://github.com/SovereignCloudStack/standards/pull/1266)
  - don't change flavor names (breaks too many existing installations)
  - besides, we want to move away from encoding information in names
  - use setting in extra_specs
  - everyone is invited to review!
