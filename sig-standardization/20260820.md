### CRUD API for KaaS clusters

sponsor: @schnatterer

- feature request [standards#1264](https://github.com/SovereignCloudStack/standards/issues/1264)
  - currently discussion if single API vs. minimal set of upstream APIs vs. no API
- Current scope of KaaS standardization is to provide standard interfaces/behavior for apps/workloads running on K8s clusters
  - Cluster management was deliberately kept out of scope
  - Cluster management is desirable though
    - Attempts to unify existing solutions (CAPI-based and Gardener and ...) thus far not successful
    - Meta-API is hard to find acceptance for
      - SECA-API?
    - https://xkcd.com/927/ ^^
    - minimal requirement of such an API could be to deploy an SCS-compatible cluster (as it is [already the case with the test suite plugins](https://github.com/SovereignCloudStack/standards/tree/main/Tests/kaas/plugin))
      - testing use case not comparable to real-world use cases (minimal setup to just pass the tests and save resources)
    - differentiation between standard and implementation
      - standard could only define there must be an API
      - implementations can be vendor-specific
- Suggestion to prioritize issues/pains users find when migrating/redeploying workloads between clusters of different providers
  - Storage, Network, Loadbalancers, Security, ...
  - User-centric is key here
  - more on this see next topic

### SCS-compatible KaaS v2

sponsor: @depressiveRobot

- What should be part of the next scope v2?
- focus should be on issues when moving workloads between KaaS environments of different providers
- suggestions
  - provisioning of clusters (see discussion above)
  - storage
    - e.g. S3 for backups
    - default storage provider needed
    - Storage use case: RWX <- only specific backends offer that, quite a couple of workloads rely on it
    - IaaS standard can be reused for that
  - network
    - for some K8s versions, Cilium took more than three months to provide official support
  - loadbalancers
  - security
    - Privilege management
    - Common minimum requirements ... (e.g. mitigation of CPU speculation issues)
- More Requirements to K8s
  - ingress
  - public IP
