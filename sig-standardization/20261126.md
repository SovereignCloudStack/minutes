### Self-description for SCS-compatible KaaS environments

sponsor: @depressiveRobot

- Issue [standards#1309](https://github.com/SovereignCloudStack/standards/issues/1309)
- trade-off between brevity of the self-description and flexibility for the providers
  - be advised that flexibility for the provider means fragmentation and complexity for the user!
  - "curse of dimensionality": five features with three options each makes for (calculating...) $3^5 = 243$ possible configurations
  - however, some features we won't standardize any time soon (such as the API for provisioning clusters), so no 'fragmentation' is to be expected; and in this case, we can use self-description without harm
- implement a proof of concept before standardizing it
  - iterate upon it together with several providers!
- proposal @depressiveRobot
  - each SCS standard can define its part of the self-description
- discuss again in one of the next meetings
